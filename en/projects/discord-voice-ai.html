01The problem

I wanted to be able to talk to an AI assistant inside a Discord voice channel, as just another participant, without having to type a command for every question.

02The solution

A Python bot built with discord.py and its voice receive extension. A custom sink receives each user's PCM audio, detects speech and silence by calculating the energy (RMS) and, when someone finishes talking, sends the clip to Whisper for transcription.

The transcript goes to an LLM that writes a short, conversational reply, which is synthesized with TTS and played in the channel through FFmpeg.

04Key features

Continuous listening

!join and !leave commands; from then on the bot listens with no further interaction.

Per-user buffers

Each person has their own buffer and state, so several people can talk in the same channel.

End of sentence

Energy threshold and minimum duration to ignore noise and clips that are too short.

Doesn't hear itself

While it plays a reply, the bot ignores incoming audio.

Async processing

Transcription, reply and synthesis run in the background without blocking audio reception.

No leftovers

Intermediate WAV and MP3 files are deleted after use.

06Technical challenges

  1. Knowing when someone has finished talking

    No external VAD: RMS is calculated by hand for each PCM packet, with a silence threshold and a minimum audio length so noise isn't transcribed.

  2. Threads and the event loop

    The sink receives audio on a different thread from asyncio; processing is scheduled with run_coroutine_threadsafe so neither one blocks.

  3. Avoiding echo loops

    The bot drops incoming audio while it's speaking so it doesn't transcribe its own reply.

07Results

  • Natural voice conversation with an LLM inside Discord.
  • Several users in the same channel, each with their own buffer.
  • A base for experimenting with near real-time voice assistants.

08Code

main.py (simplified excerpt)
class ContinuousSink(voice_recv.AudioSink):
    SILENCE_THRESHOLD = 500   # RMS amplitude
    SILENCE_DURATION = 1.2    # seconds of silence = end of sentence

    def wants_opus(self):
        return False          # we want PCM

    def write(self, user, data):
        if user is None or self.voice_client.is_playing():
            return            # don't listen to itself

        pcm = data.pcm
        samples = struct.unpack(f"<{len(pcm) // 2}h", pcm)
        rms = math.sqrt(sum(s * s for s in samples) / len(samples)) if samples else 0
        now = time.time()

        rec = self.user_data.setdefault(user.id, {"buffer": bytearray(), "last": now, "busy": False})
        if rec["busy"]:
            return

        if rms > self.SILENCE_THRESHOLD:
            rec["buffer"].extend(pcm)
            rec["last"] = now
        elif rec["buffer"] and now - rec["last"] > self.SILENCE_DURATION:
            audio, rec["buffer"], rec["busy"] = bytes(rec["buffer"]), bytearray(), True
            asyncio.run_coroutine_threadsafe(self.process_audio(user, audio), self.bot.loop)

09What I learned

Working with real-time audio makes you think about latency: every stage (detection, transcription, reply and synthesis) adds up, and how smooth it feels depends on trimming all of them.
