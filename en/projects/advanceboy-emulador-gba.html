01The problem

I wanted a GBA emulator for Android with everything I expect as a player (save states with thumbnails, fast forward, rewind, physical controllers, cartridge sensors) and, at the same time, a project to step away from the web and work with native code, graphics and real-time audio.

02The solution

The app is written in Kotlin and uses mGBA as its core, compiled with the NDK and CMake. A custom JNI bridge exposes what the Kotlin side needs: loading ROMs, stepping frames, audio, save states and cheats.

Rendering goes through OpenGL ES with selectable shaders, and the emulation thread is paced by the audio itself. GitHub Actions runs core tests with test ROMs, builds the APK on every push and publishes releases on tags.

03Architecture and flow

  1. ROMLibrary with folder scanning: .gba, .gb, .gbc and .zip

From 0.1× slow motion up to 8× or unlimited fast forward, plus rewind by holding a button.

GameShark, Action Replay, CodeBreaker and Game Genie with automatic format detection.

Real-time clock, rumble, tilt, gyroscope and solar sensor mapped to the phone's sensors.

Bluetooth and USB with button remapping.

06Technical challenges

  1. Syncing video and audio

    At normal speed, the blocking audio write sets the pace (the GBA produces exactly one second of audio per emulated second). When muted, fast-forwarding or rewinding, a 59.73 Hz timer takes over.

  2. A single thread for the core

    Everything that touches the native core has to run on the emulation thread. Other threads send it work through a concurrent queue.

  3. Storage on modern Android

    Since Android 11, file managers can't open Android/data. Saves are exposed through a custom DocumentsProvider.

  4. Reproducible releases

    The workflow checks that the tag matches versionName and always signs with the same key, so each APK installs over the previous one without losing saves.

08Code

EmulatorThread.kt (excerpt)
/**
 * Runs the emulator: one loop iteration = one emulated frame.
 *  - Normal speed with sound: the blocking audio write sets the pace.
 *  - Muted, fast forward or rewind: 59.73 Hz timer.
 * Everything that touches the native core runs on this thread; everything else uses post().
 */
class EmulatorThread(
    private val frameBuffer: FrameBuffer,
    private val audio: AudioOutput,
    private val callbacks: Callbacks,
) : Thread("Emulator") {

    @Volatile var fastForward = false
    @Volatile var rewinding = false
    private val tasks = ConcurrentLinkedQueue<Runnable>()

    fun post(task: Runnable) {
        tasks.add(task)
        wake()
    }

    override fun run() {
        Process.setThreadPriority(Process.THREAD_PRIORITY_URGENT_DISPLAY)
        var nextFrameTime = System.nanoTime()
        while (true) {
            runPendingTasks()
            if (quitRequested) break
            if (paused) { waitWhilePaused(); continue }

            nextFrameTime = when {
                rewinding -> stepRewind(nextFrameTime)
                fastForward -> stepFastForward(nextFrameTime)
                else -> stepNormal(nextFrameTime)
            }
            if (NativeBridge.pollRumble()) callbacks.onRumble()
        }
    }
}
