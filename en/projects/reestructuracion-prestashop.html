01The problem

The store was carrying a theme full of piled-up customizations and third-party modules that didn't fit the way the company sells.

The best-selling products in each category weren't highlighted, company components were inconsistent across shops, and some bulk catalog operations were slow.

02The solution

I rebuilt the presentation layer starting from the base theme and developed custom PHP modules following PrestaShop's architecture: hooks, back office configuration and Smarty templates.

The product blocks are fed by optimized, multistore-aware SQL queries, with caching so they don't slow down page loads.

06Technical challenges

  1. Multistore in every query

    In a multistore setup it's easy to mix data between shops. Every query filters by id_shop on orders, product_shop and per-language texts.

  2. Performance

    Calculating the best sellers on every visit would be expensive: the result is cached per shop and category.

  3. Maintainability

    The logic lives in modules, not in the core, so the platform can be updated without losing changes.

07Results

  • Best-selling products are highlighted automatically in each category.
  • Consistent company components across all shops.
  • Faster bulk catalog operations after optimizing the queries.

08Code

topsellersbycategory.php (excerpt)
<?php
class TopSellersByCategory extends Module
{
    public function hookDisplayCategoryTop(array $params)
    {
        $idShop     = (int) $this->context->shop->id;
        $idCategory = (int) Tools::getValue('id_category');
        $cacheId    = 'topsellers_' . $idShop . '_' . $idCategory;

        if (!Cache::isStored($cacheId)) {
            $sql = new DbQuery();
            $sql->select('od.product_id, SUM(od.product_quantity) AS qty')
                ->from('order_detail', 'od')
                ->innerJoin('orders', 'o', 'o.id_order = od.id_order AND o.valid = 1 AND o.id_shop = ' . $idShop)
                ->innerJoin('category_product', 'cp', 'cp.id_product = od.product_id AND cp.id_category = ' . $idCategory)
                ->innerJoin('product_shop', 'ps', 'ps.id_product = od.product_id AND ps.id_shop = ' . $idShop . ' AND ps.active = 1')
                ->where('o.date_add >= DATE_SUB(NOW(), INTERVAL 90 DAY)')
                ->groupBy('od.product_id')
                ->orderBy('qty DESC')
                ->limit(8);

            Cache::store($cacheId, Db::getInstance(_PS_USE_SQL_SLAVE_)->executeS($sql));
        }

        $this->context->smarty->assign('top_products', Cache::retrieve($cacheId));

        return $this->display(__FILE__, 'views/templates/hook/topsellers.tpl');
    }
}

Internal project: the source code is private. This snippet is simplified, with no credentials or business data.

09What I learned

In PrestaShop, respecting the platform's architecture (hooks, modules, DbQuery) is what separates a maintainable customization from a theme that can never be updated.
